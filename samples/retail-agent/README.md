# Retail — Promotion Agent

A stateful, event-driven real-time offer decisioning pipeline built on the Event Rule Agent pattern:
customer interactions and purchases are evaluated by an IBM Decision Intelligence archive to offer the most appropriate promotions for the customer at the moment of interaction.

## Overview

| | |
|---|---|
| **Agent** | `retail-promotion-agent` |
| **Entity tracked** | `Customer` (keyed by `$.customerContext.customerId`) |
| **Decision archive** | [`RetailDecisionService_<version>.jar`](RetailDecisionService_1.0.0.jar) |
| **State TTL** | 6 months (RocksDB) |
| **Descriptor** | [`agents.json`](agents.json) |

### Entity changelog

When `stateConfig.changeLogTopic` is set (this agent uses `agent-customer-entity-changelog`), a
side-output record is emitted to that topic whenever the rule engine returns an updated
`CustomerContext` entity. Each record has the form:

```json
{
  "entityId":   "CUST-001",
  "entityType": "Customer",
  "timestamp":  1750000000000,
  "entity":     { "customerId": "CUST-001", "status": "Gold", ["..."] }
}
```

## 5. Running This Use Case

**From the project root**, after the infrastructure is up (see the
[main README Quick Start](../../README.md#4-quick-start)):

```bash
# 1. Build the project (if not already built)
./build.sh

# 2. Start the infrastructure
./run.sh up

# 3. Deploy this use case
./samples/retail-agent/scripts/deploy.sh

# 4. Open the dashboard
open http://localhost:3010
```

Click **Retail — Promotion Agent** in the use-case selector, then click any scenario button
in the **Send Events** panel.
